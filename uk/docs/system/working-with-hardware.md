# Робота з обладнанням

!!! abstract "Огляд"

    Як WildcoreDMS підключається до обладнання, звідки беруться параметри підключення, як
    працює кешування відповідей і як отримати «живі» дані.

## Способи взаємодії

WildcoreDMS працює з обладнанням через:

- **SNMP v1/v2c** — основне джерело даних: стан портів і ONU, лічильники, FDB, рівні сигналу;
- **консоль (Telnet/SSH)** — дані, недоступні по SNMP, реєстрація ONU, [макроси](../components/macros/getting-started.md), [веб-консоль](../components/console.md);
- **API** — для Mikrotik RouterOS;
- **ICMP** — перевірка доступності пристрою перед зверненням до нього (можна вимкнути параметром `SWC_CHECK_ICMP_PING`).

Що саме можна отримати з конкретної моделі, залежить від її набору модулів. Перелік модулів
пристрою показує команда:

```shell
wca switcher-core:modules <IP пристрою>
```

Повний перелік моделей і можливостей — [Список обладнання](../supported-hardware.md).

## Параметри підключення: звідки беруться { #connection-levels }

Облікові дані та параметри підключення задаються на кількох рівнях. Кожен наступний рівень
перекриває попередній:

```
система (.env / веб) → доступ → модель → пристрій
```

| Рівень | Де задається | Що можна задати |
|--------|--------------|-----------------|
| **Система** | `Конфігурація > Конфігурація системи` → «Робота з пристроями» або `.env` — див. [Налаштування системи (.env)](../installation-and-updating/env-configuration.md#swc) | Значення за замовчуванням для всіх пристроїв |
| **Доступ** | [`Керування пристроями > Доступи`](../management/device-access.md) | Community, логін/пароль, тип консолі, порти, тайм-аути, версія SNMP |
| **Модель** | [Додаткові параметри моделі](../management/custom-parameters.md#sw_core_connection) | Облікові дані (`access`) та параметри підключення (`sw_core_connection`) |
| **Пристрій** | [Додаткові параметри пристрою](../management/custom-parameters.md#sw_core_connection) | Те саме, що для моделі — для одного пристрою |

Не всі параметри доступні на кожному рівні:

| Параметр | Система (веб / `.env`) | Доступ (веб) | Модель / пристрій (JSON) |
|----------|:----------------------:|:------------:|:------------------------:|
| Тип консолі (Telnet/SSH) | ✓ | ✓ | ✓ |
| Порт консолі | ✓ | ✓ | ✓ |
| Тайм-аут консолі | ✓ | ✓ | ✓ |
| Очікування даних консолі | ✓ | — | ✓ |
| Версія SNMP | ✓ | ✓ | ✓ |
| Порт SNMP | ✓ | ✓ | ✓ |
| Тайм-аут і повтори SNMP | ✓ | ✓ | ✓ |
| Порт API Mikrotik | ✓ | — | ✓ |
| Community, логін, пароль | — | ✓ | ✓ |
| Кількість одночасних запитів до обладнання | лише `.env` | — | — |
| Час життя кешу відповідей | лише `.env` | — | — |

## Кеш і «живі» дані

WildcoreDMS прагне показувати актуальні дані з обладнання, але щоб сторінки відкривалися
швидко, відповіді обладнання **кешуються**. Дані в кеші вважаються актуальними протягом часу,
заданого параметром `SWC_CACHE_ACTUALIZE_TIMEOUT_SEC`; після цього вони запитуються з
обладнання знову.

На сторінці пристрою, порту чи ONU блок **«Виклик пристрою»** показує, звідки взято кожен тип даних:

- **з кешу (час)** — дані з кешу та коли вони були отримані;
- **Онлайн** — дані щойно отримані з обладнання.

Щоб отримати свіжі дані, натисніть **«Оновити»** на сторінці — запит до обладнання може
тривати 15–30 секунд і довше для великих OLT.

!!! info
    Частина даних (графіки, історія рівнів сигналу, аналітика) береться з історії опитувань,
    а не з обладнання напряму, тому кнопка «Оновити» їх не змінює. Історія оновлюється
    [опитувачем](./poller.md) за розкладом.

## Налаштування роботи з окремою моделлю чи пристроєм

Поведінку для конкретного обладнання змінюють **додаткові параметри** моделі або пристрою:
локальні описи PON-портів, набір даних для списку та картки ONU, формат серійних номерів
Huawei, автоматична діагностика кабелю тощо — див.
[Додаткові параметри моделей і пристроїв](../management/custom-parameters.md).
