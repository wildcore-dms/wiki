# Компонент «Діагностика» (diagnostic)

!!! abstract "Огляд"

    API для діагностики з зовнішніх систем (білінг, CRM): діагностика порту/ONU абонента, ARP-пінг, ICMP-пінг, traceroute. Використовується [інтеграціями з білінгами](./mikbill_integration.md), щоб оператор бачив стан абонента, не відкриваючи WildcoreDMS.

## Як працює

Зовнішня система (білінг) звертається до API з [API-ключем](../web-interface/api-key-generation.md) користувача WildcoreDMS і передає ID інтерфейсу абонента (зазвичай він зберігається в білінгу після синхронізації).

WildcoreDMS визначає тип обладнання та виконує відповідні запити: для порту комутатора — стан лінка, помилки, MAC-адреси, діагностика кабелю; для ONU — статус, сигнал, причина відключення, MAC-адреси тощо.

Результат повертається у JSON або як готова **HTML-картка**, яку білінг вбудовує у картку абонента. Також можна отримати посилання на сторінку інтерфейсу у WildcoreDMS.

## Методи API

| Метод | Опис |
|---|---|
| `GET /api/v1/component/diagnostic/interface/{id}/diag` | Діагностика інтерфейсу (JSON): стан, сигнал, помилки, MAC — залежно від типу обладнання |
| `GET /api/v1/component/diagnostic/interface/{id}/diag/html` | Те саме у вигляді HTML-картки для вбудовування в білінг |
| `GET /api/v1/component/diagnostic/interface/{id}/links` | Посилання на сторінки інтерфейсу у веб-інтерфейсі WildcoreDMS |
| `GET /api/v1/component/diagnostic/arp-ping` | ARP-пінг IP-адреси з маршрутизатора |

## Права

| Право | Що дозволяє |
|---|---|
| **ARP-пінг** | ARP-пінг |
| **ICMP-пінг** | ICMP-пінг |
| **Traceroute** | Traceroute |
| **Діагностика інтерфейсу (для білінгу)** | Діагностика інтерфейсу |

!!! note
    Для доступу з білінгу створіть окремого користувача з потрібною роллю та [API-ключем](../web-interface/api-key-generation.md). Повний опис методів — [API](../api/index.md).

## Увімкнення

Компонент вмикається в `Конфігурація > Конфігурація системи` → вкладка «Компоненти» або командою:

```shell
sudo wca component:control diagnostic enable
```
