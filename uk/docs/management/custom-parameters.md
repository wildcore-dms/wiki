# Додаткові параметри моделей і пристроїв

!!! abstract "Огляд"

    Блок **«Додаткові параметри»** у картці [моделі](./device-models.md) та
    [пристрою](./devices.md) — це JSON з параметрами, які змінюють поведінку WildcoreDMS для
    конкретного обладнання: облікові дані та параметри підключення, які дані завантажувати,
    формат серійних номерів, резервне копіювання тощо.

## Де задаються і що має пріоритет

- **Модель** (`Керування пристроями > Моделі` → модель → «Додаткові параметри») — параметри діють
  для всіх пристроїв цієї моделі. Для частини моделей параметри вже задані за замовчуванням.
- **Пристрій** (`Керування пристроями > Пристрої` → пристрій → «Додаткові параметри») — параметри
  діють лише для цього пристрою і **мають пріоритет** над параметрами моделі.

Для параметрів підключення порядок такий (кожен наступний рівень перекриває попередній):

```
загальні налаштування системи → доступ → модель → пристрій
```

!!! info "Як редагувати"
    Редактор JSON має два режими: **Tree** (дерево) та **Code** (текст). Для введення параметрів
    вручну перемкніть режим на **Code** у панелі інструментів редактора, вставте JSON і збережіть
    картку. Кілька параметрів записуються в одному об'єкті:

    ```json
    {
      "load_snooping_info": true,
      "enable_auto_cable_diag": true
    }
    ```

    Не видаляйте параметри, яких немає в цьому описі: частина з них заповнюється системою
    (наприклад, налаштування опитувачів та інтеграцій).

## Перелік параметрів

| Параметр | Де | Тип обладнання | Призначення |
|----------|----|----------------|-------------|
| [`access`](#access) | модель, пристрій | усі | Власні облікові дані замість доступу |
| [`sw_core_connection`](#sw_core_connection) | модель, пристрій | усі | Порти, протокол консолі, тайм-аути, версія SNMP |
| [`disable_save_description_on_physical_ifaces`](#disable_save_description_on_physical_ifaces) | модель, пристрій | OLT | Локальні описи PON-портів |
| [`load_snooping_info`](#load_snooping_info) | модель, пристрій | OLT | Автоматично завантажувати DHCP Snooping в картці ONU |
| [`modules_loading`](#modules_loading) | модель, пристрій | OLT | Які дані завантажувати у списку ONU та картці ONU |
| [`show_optical_info_from_history`](#show_optical_info_from_history) | модель | OLT | Рівні сигналу у списку ONU з історії, а не з обладнання |
| [`optical_load_only`](#optical_load_only) | модель | OLT | Які оптичні показники запитувати у списку ONU |
| [`sn_as_ascii`](#sn_as_ascii) | модель, пристрій | Huawei OLT | Формат серійного номера ONU |
| [`epon_description_block_index`](#epon_description_block_index) | модель, пристрій | ZTE OLT (EPON) | Яку частину опису EPON ONU показувати |
| [`enable_auto_cable_diag`](#enable_auto_cable_diag) | модель, пристрій | комутатори | Автоматична діагностика кабелю при відкритті порту |
| [`oxidized`](#oxidized) | модель, пристрій | усі | Налаштування резервного копіювання конфігурації |
| [`disabled_modules`](#disabled_modules) | пристрій | пристрої моніторингу | Вимкнути окремі датчики/модулі |

## Облікові дані та підключення

### `access` { #access }

Облікові дані, що перекривають значення з [доступу](./device-access.md). Зручно, коли для
окремої моделі або пристрою пароль відрізняється, а створювати окремий доступ не хочеться.

```json
{
  "access": {
    "login": "admin",
    "password": "secret",
    "public_community": "public",
    "private_community": "private"
  }
}
```

Можна вказати лише потрібні поля — решта береться з доступу.

### `sw_core_connection` { #sw_core_connection }

Параметри підключення до обладнання для моделі або окремого пристрою. Системні значення за
замовчуванням задаються в [Конфігурації системи або `.env`](../installation-and-updating/env-configuration.md#swc),
більшість із них — також у [доступі](./device-access.md#connection). Ключі `console_wait_byte_sec`
та `mikrotik_api_port` у формі доступу відсутні — для окремого обладнання їх можна задати лише тут.
Зведена таблиця рівнів — [Робота з обладнанням](../system/working-with-hardware.md#connection-levels).

```json
{
  "sw_core_connection": {
    "console_connection_type": "ssh",
    "console_port": 2222,
    "console_timeout_sec": 120,
    "console_wait_byte_sec": 10,
    "snmp_version": "2c",
    "snmp_port": 161,
    "snmp_timeout_sec": 5,
    "snmp_repeats": 3,
    "mikrotik_api_port": 8728
  }
}
```

| Ключ | Опис |
|------|------|
| `console_connection_type` | `telnet` або `ssh` |
| `console_port` | Порт консолі |
| `console_timeout_sec` | Максимальний час виконання консольної команди, сек |
| `console_wait_byte_sec` | Скільки чекати на наступні дані від консолі, перш ніж вважати вивід завершеним, сек (типово 10). Збільшіть для обладнання, яке «замислюється» посеред виводу |
| `snmp_version` | `1` або `2c` |
| `snmp_port` | Порт SNMP |
| `snmp_timeout_sec` | Тайм-аут одного SNMP-запиту, сек |
| `snmp_repeats` | Кількість повторів SNMP-запиту |
| `mikrotik_api_port` | Порт API для Mikrotik RouterOS |

Вказуйте лише ті ключі, які треба змінити.

## OLT

### `disable_save_description_on_physical_ifaces` { #disable_save_description_on_physical_ifaces }

Вимикає збереження та синхронізацію описів **PON-портів** з обладнання — описи портів
можна вести локально у WildcoreDMS. Описи ONU при цьому продовжують синхронізуватися.

```json
{ "disable_save_description_on_physical_ifaces": true }
```

### `load_snooping_info` { #load_snooping_info }

Вмикає **автоматичне** завантаження таблиці [DHCP Snooping](../system/dhcp-snooping.md) разом з
іншою інформацією про ONU. Без параметра таблицю в картці ONU можна запросити кнопкою
«Отримати інформацію». За замовчуванням вимкнено: на частині моделей прив'язки до ONU
визначаються через таблицю FDB, і це може помітно сповільнювати відкриття картки ONU.

```json
{ "load_snooping_info": true }
```

### `modules_loading` { #modules_loading }

Обмежує набір даних, що завантажуються для **списку ONU** (`ont_list`) та **картки ONU**
(`ont_info`). Допомагає прискорити роботу з великими або повільними OLT: завантажуються лише
перелічені дані, решта пропускається.

```json
{
  "modules_loading": {
    "ont_list": ["pon_onts_status", "pon_onts_serial", "interface_descriptions"],
    "ont_info": ["pon_onts_status", "pon_onts_optical", "pon_onts_vendor", "fdb"]
  }
}
```

Можна задати лише одну з секцій — друга працюватиме як зазвичай (завантажуються всі дані,
які підтримує модель).

| Значення | `ont_list` | `ont_info` | Що завантажується |
|----------|:----------:|:----------:|-------------------|
| `pon_onts_status` | ✓ | ✓ | Статус ONU |
| `pon_onts_serial` | ✓ | ✓ | Серійний номер (GPON) |
| `pon_onts_mac_addr` | ✓ | ✓ | MAC-адреса (EPON) |
| `interface_descriptions` | ✓ | ✓ | Опис |
| `pon_onts_optical` | ✓ | ✓ | Рівні сигналу |
| `sfp_optical` | ✓ | | Оптика SFP PON-порту |
| `pon_onts_vendor` | | ✓ | Виробник, модель, версії ONU |
| `pon_onts_reasons` | | ✓ | Причини відключення |
| `pon_onts_down_history` | | ✓ | Історія відключень |
| `pon_onts_configuration` | | ✓ | Конфігурація ONU |
| `interface_counters` | | ✓ | Лічильники трафіку/помилок |
| `fdb` | | ✓ | Таблиця MAC-адрес за ONU |
| `onu_ip_host` | | ✓ | IP-адреса ONU |
| `uni_interfaces_status` | | ✓ | Стан Ethernet-портів ONU |
| `uni_interfaces_vlans` | | ✓ | VLAN на портах ONU |
| `snooping_info` | | ✓ | DHCP Snooping (також потребує [`load_snooping_info`](#load_snooping_info)) |

!!! warning
    Значення має бути об'єктом зі списками. Помилка у форматі (наприклад, рядок замість
    списку) призведе до помилки завантаження списку/картки ONU.

### `show_optical_info_from_history` { #show_optical_info_from_history }

Задається **на моделі**. Коли увімкнено, рівні сигналу у списку ONU беруться з історії
опитувань, а не запитуються з обладнання при кожному відкритті — список відкривається швидше.
Для більшості моделей OLT увімкнено за замовчуванням.

```json
{ "show_optical_info_from_history": false }
```

### `optical_load_only` { #optical_load_only }

Задається **на моделі** і діє, лише коли `show_optical_info_from_history` вимкнено.
Перелік оптичних показників, які запитуються з обладнання для списку ONU, через кому.
Типово — `rx,temp,distance`.

```json
{ "optical_load_only": "rx,olt_rx,temp,distance" }
```

Доступні значення: `rx`, `tx`, `olt_rx`, `temp`, `voltage`, `distance` (залежить від моделі).

### `sn_as_ascii` { #sn_as_ascii }

**Huawei OLT.** Показувати серійні номери ONU (у списку ONU та серед незареєстрованих) у
текстовому вигляді `HWTC1234ABCD` замість шістнадцяткового `48575443...`.

```json
{ "sn_as_ascii": true }
```

### `epon_description_block_index` { #epon_description_block_index }

**ZTE OLT, EPON ONU.** Якщо опис ONU складається з кількох частин, розділених `$$`
(наприклад, `договір$$адреса$$телефон`), параметр задає номер частини, яку показувати
(нумерація з `0`). За замовчуванням показується остання частина.

```json
{ "epon_description_block_index": 1 }
```

## Комутатори

### `enable_auto_cable_diag` { #enable_auto_cable_diag }

Автоматично запускати діагностику кабелю при відкритті інформації про порт (для моделей, що
її підтримують). За замовчуванням вимкнено: діагностика займає додатковий час, а на частині обладнання
може ненадовго переривати лінк на порту.

```json
{ "enable_auto_cable_diag": true }
```

## Резервне копіювання конфігурації

### `oxidized` { #oxidized }

Потрібен компонент [Бекапи конфігурації](../components/oxidized.md). Для підтримуваних моделей
налаштування вже задані системою; параметр дозволяє перевизначити їх або налаштувати бекап для
моделі, якої немає в переліку.

```json
{
  "oxidized": {
    "model": "ios",
    "enable": false,
    "remove_secret": false
  }
}
```

| Ключ | Опис |
|------|------|
| `model` | Назва моделі в Oxidized (`ios`, `nxos`, `routeros`, `junos`, `bdcom`, ...) — див. [список моделей Oxidized](https://github.com/ytti/oxidized/blob/master/docs/Supported-OS-Types.md) |
| `enable` | Переходити в привілейований режим (`enable`) перед зняттям конфігурації |
| `remove_secret` | Прибирати паролі та ключі з конфігурації |

Сам бекап для пристрою вмикається перемикачем **«Ввімкнути бекапи (Oxidized)»** у картці пристрою.

## Пристрої моніторингу

### `disabled_modules` { #disabled_modules }

Список модулів [пристрою моніторингу](../components/sensors.md), які не треба опитувати —
наприклад, якщо датчик не підключений і пристрій повертає помилку.

```json
{ "disabled_modules": ["<назва модуля>"] }
```

Назви модулів конкретного пристрою можна переглянути командою
`wca switcher-core:modules <IP пристрою>`.

## Службові параметри

Ці параметри заповнюються системою через інтерфейс або інтеграції — редагувати їх вручну не потрібно:

| Параметр | Чим керується |
|----------|---------------|
| `poller_config` | Блок «Налаштування опитувача» в картці моделі/пристрою |
| `oxidized_enabled` | Перемикач «Ввімкнути бекапи (Oxidized)» |
| `sensors` | Налаштування датчиків на сторінці пристрою моніторингу |
| `userside` | Інтеграція з Userside |
